# FIX — SR-4 (per-PCN lines), SR-3 (ACI PN identity), ZSUB label
**Date:** 2026-07-22 · Staging only (docker :5002). Not prod, not Theresa-confirmed.
Applies to ALL jobs (helpers keyed by job). Companion to FIX-ZSUB-PRIMARY-2026-07-22.md.

## SR-4 — each PCN as its own line
Before: the `inv` CTE did `GROUP BY aci_pn` + `SUM(onhandqty+floor)` and kept one PCN via
`array_agg(pcn)[1]`, so a part sitting in several PCNs showed a single lumped total. 6588L
alone had 41 lines with >1 PCN (line 79 = 7 PCNs); 2,895 aci_pns across all jobs are multi-PCN.

Fix (additive, no change to the core query / shortage math): new helper
`own_pcn_rows_by_acipn(cursor, job)` returns the job's own stock **one row per PCN**
(qty = bin + MFG-Floor per PCN; rows sum to the line total). Rendered as blue **"PCN"**
sub-rows under the primary line, ONLY when a line has >1 PCN. Wired into the shortage report
view, the Excel export, and the job-detail form. ACI PN cell = `<aci_pn> (PCN)`.

## SR-3 — same-MPN visibility rows no longer masquerade as a wrong ACI PN
The SR-2 "same MPN under another part number" rows were putting the OTHER job's PN in the
ACI PN column (e.g. `6590L-A-9` under the `6588L-2` line), which read as "wrong ACI PN".
Now the ACI PN column stays the JOB's line (`6588L-2` + grey "SAME MPN" badge); the other PN
where the stock physically sits moves to the ITEM column. View + export updated.
(The stranded-stock cause of SR-3 was already fixed in deployed code, commit c90f731.)

## ZSUB label (follow-up to the ZSUB visibility feature)
Per Preet: a ZSUB sub-row's ACI PN cell now shows `<aci_pn> (ZSUB)` (e.g. `6588L-1 (ZSUB)`)
instead of a bare "ZSUB" badge — so it's clearly the line's part, marked as its substitute.
View + export + form updated.

## Verified (staging, 6588L)

`(ZSUB)`, 136 `(SAME MPN)`. Line 79's 7 PCNs sum to 116 (matches the line on-hand).
Behavioral gate green (p1/p2/p5). Rebuilt + redeployed; container healthy.
