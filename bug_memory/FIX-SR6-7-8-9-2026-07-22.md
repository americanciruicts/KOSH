## SR-8/9 — MFG Floor never counts (the big one)
Rule (Preet): a row located at **MFG Floor** is parts already picked/out for a job — a
STATUS, not available stock — so on-hand for it is **always 0**. `mfg_qty` is ignored
entirely (a bin row carrying mfg_qty is bad data).

Change: on-hand = `SUM(onhandqty)` counting **only** rows where `loc_to <> 'MFG Floor'`.
Dropped the old `+ mfg_qty` term. Applied to: `_SHORTAGE_MATCH_SQL` inv CTE, both
job-detail inv CTEs, and the ZSUB + per-PCN helpers. The report/form never show a
"MFG Floor" location now, and a line whose stock is all on the floor reads 0.

**IMPACT — verify with Preet/Theresa:** this reverses the old "count the floor" behavior
(bug #9), so many lines flip to shortage. 6366L: shortage count **5 → 30** (≈25 lines have
their stock on the floor). Export (drops 0-on-hand) then shows only bin-stocked lines.

## SR-6 — QTY/REQ showed 0
The strict regex `bl.qty ~ '^[0-9]+...$'` zeroed any qty with a comma ("1,000"), unit
("2 EA"), or space; REQ = ceil(qty*order_qty) followed to 0. Change: strip commas then take
the first numeric token via `(regexp_match(replace(qty,',',''), '[0-9]+(?:[.][0-9]+)?'))[1]`.
NOTE: first attempt used `substring(str FROM '...(group)...')` which returns the *group* not
the whole match → every qty came out 0; fixed with regexp_match. Applied to report + both
job-detail qty columns. Verified: 6366L-4 qty 0 → **7**.

## SR-7 — own stock omitted (case-sensitive join)
Both job-detail inv CTEs joined `ON w.item = bl.aci_pn` (case-SENSITIVE), so mixed-case
stock was missed (qty_on_hand=0). Fixed to `ON UPPER(w.item)=UPPER(bl.aci_pn)` (the report
copy was already case-insensitive). MPN-based own-stock matching was intentionally NOT added.
